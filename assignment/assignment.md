\# The Assignment

Build an application that returns the five closest Jumbo stores to a given position.



Your application should accept an input position, consisting of a latitude and longitude, and return the five nearest stores to that position.



\# Seed Data



A JSON file is attached to this assignment. You should use this file as the source of store data for your application.



The file contains a list of Jumbo stores. Each store includes, among other fields:

* City
* Postal Code
* Address Name
* Latitude
* Longitude



Your application should load and use this data when determining the nearest stores.



\# Rules



\*\*It has to be Java\*\*

Which frameworks and libraries you use is entirely up to you.

We want to see your \*\*REST API skills\*\*. The solution should expose its functionality through a REST API.



Write it as if it were production code, as much as is reasonable within a small assignment.



Make it easy for the reviewer to run.



We should be able to build and start your application by following your README.



Feel free to add any additional features you think are cool. This is your space to show us something.



\# Practical Details



\*\*Keep it simple.\*\* A working solution can be built in a few hours. We are not looking for a large system.



You decide how production-ready to make it.



Tests, logging, monitoring, error handling, documentation, the choices you make (and the ones you consciously leave out) are yours, and we will talk about them.



\*\*Focus on backend.\*\* This is a backend role, so there is no need for any frontend or UI. Please do not spend time on one.



Share your code on GitHub. Please make the repository available to us via a GitHub link. We have had issues with zip files in the past, so a repository link is strongly preferred.

You are welcome to use AI-assisted tools (Copilot, ChatGPT, etc.). We use them too.

\# What Happens Next

After you submit, we will schedule a technical interview built around your solution. We will ask you to walk us through your code, explain the decisions you made, discuss the trade-offs you accepted, and talk about what you would change or add with more time.



The conversation matters as much as the code. We are far more interested in how you reason about your solution than in whether every edge case is covered. A simpler solution you can explain and defend well is worth more to us than a complex one you cannot.
